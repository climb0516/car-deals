# 🚗 车市行情 · 新车与降价

> 买车前看一眼：本地经销商降价榜、新车上市日历、月销量榜

**🌐 在线访问：[https://climb0516.github.io/car-deals/](https://climb0516.github.io/car-deals/)**

---

## 功能

- **顶部要点**：当前城市降幅最大的车、上月销量冠军、近 7 天上市几款新车、下一款即将上市的车（倒计时）
- **降价榜**：8 个城市（杭州默认，另有上海、北京、广州、深圳、成都、武汉、南京）本地经销商报价，每城前 100 个车系；按价位（10 万以下 / 10–20 / 20–30 / 30 万以上）、品牌筛选，按降幅或降价金额排序；显示现价、最高降多少万、降幅；点击跳转懂车帝车系页
- **新车日历**：即将上市（日期、倒计时、预售价）和近期已上市（日期、售价、报道家数），同一车型多家报道已合并；另附爱卡汽车「最新上市」车型列表
- **月销量榜**：近 6 个月可切换，前 30 名，名次较上月升降，新上榜标记
- 右侧：当前城市降价车系最多的品牌、怎么看降价榜、来源状态
- 深色 / 浅色主题，手机适配；选择的城市记在本机

降价信息基于本地经销商报价，「最高降」是车系里优惠最多的一款配置，实际以到店为准。

## 技术架构

```
GitHub Actions（触发：每天 09:40 北京时间定时 / 手动 dispatch / push 修改爬虫或工作流）
  ↓ python scraper.py（Python 3.12，只用标准库）
  ↓ 懂车帝排行榜接口：8 城降价榜 × 2 页 + 近 6 个月销量榜（已结束月份复用旧数据）
  ↓ Google News RSS × 3 组关键词 → 标题解析出车型 / 售价 / 上市日期
  ↓ 爱卡汽车新车频道网页解析（补充）
  ↓ 单个来源失败时沿用 data.json 里的旧数据，并在 sources 里标记
  ↓ 写入 data.json 并 commit + push（updated 每次都变 = 心跳）
       ↓
GitHub Pages（index.html）
  ↓ fetch('data.json', no-cache)，城市 / 价位 / 品牌筛选和排序都在前端完成
  ↓ 详情抽屉 #/item/<类型>/<id> + 列表页 #/list/<key>（通用组件 kit）
```

## 数据来源

| 来源 | 方式 | 每次条数 / 范围 | 备注 |
|------|------|----------------|------|
| 懂车帝 降价榜 | 接口 `rank_data?rank_data_type=52&city_name=…` | 8 城 × 2 页（offset 0 / 50，每页 50）= 每城最多 100 个车系 | `descender_price` → 最高降价（万），`count` → 最高降幅（%），`car_list[0].car_name` → 降幅最大的配置；只保留 `descender_price` 非空的条目 |
| 懂车帝 月销量 | 接口 `rank_data_type=11&month=YYYYMM` | 近 6 个月，每月 2 页，最多 100 名 | `count` → 当月销量；只有最近一个月每次重抓，其余月份已在 data.json 里就直接复用 |
| 新车上市新闻 | Google News RSS（`hl=zh-CN&gl=CN`） | 3 组关键词，去重合并后最多保留 60 条 | `正式上市 售价 万元 when:21d`（已上市）、`将于 月 日 上市 预售 when:30d`（即将上市）、`新车 上市 指导价 万 when:21d`（已上市） |
| 爱卡 最新上市 | 网页解析 [newcar.xcar.com.cn](https://newcar.xcar.com.cn/)（GB18030 解码） | 最多 20 条 | 截取页面文本「最新上市」到「车型热度排行榜」之间，按「车型名 + X万 / X-Y万」切分；无日期 |

- 请求量：降价榜 16 次 + 销量 2 次（首次无缓存时 12 次）+ 新闻 3 次 + 爱卡 1 次，日常约 22 次；降价 / 销量请求之间 `sleep 0.2s`
- **配置位置**：城市列表在 `scraper.py` 的 `CITIES`；销量月数 `SALES_MONTHS = 6`；接口地址 `RANK_API`；新闻关键词在 `launches()` 里的 `queries` 列表（每项是「搜索词, launched/upcoming」）；爱卡在 `xcar()`
- **增删城市**：改 `CITIES` 即可，前端城市切换来自 data.json 的 `cities` 字段，无需改 `index.html`
- **增删新闻关键词**：在 `queries` 里加 / 删元组，第二项决定默认归类（实际状态还会按标题里的日期再判断）
- **新增整个来源**：写一个返回 list / dict 的函数，在 `main()` 的 `data` 里用 `run("显示名", 函数, "data.json 键")` 包一层，自动获得失败兜底和来源状态

**限制**：
- 懂车帝接口没有公开文档，榜单类型编号（52 降价、11 销量）为实测结果，改版后对应模块会沿用旧数据并在来源状态里标出
- 懂车帝网页需要登录态，只能用接口；排行接口没有级别 / 能源类型字段，所以销量榜不区分燃油 / 新能源
- 新车信息从新闻标题自动提取，可能有遗漏、车型名不完整或把改款当新车

## 数据处理规则

**降价榜（`cuts()`）**：每城取 2 页，过滤掉没有 `descender_price` 的条目；`slim()` 统一字段并把图片尺寸从 `tplv-resize:640:0` 换成 `240:0`。排序不在爬虫里做，由前端 `cutList()` 完成（默认按降幅 % 降序、同降幅再按降价金额；可切换为按降价金额）。价位筛选用 `min`（指导价下限）判断区间：10 万以下 / 10–20 / 20–30 / 30 万以上。

**月销量（`sales(old)`）**：从上个月开始往前数，最多检查 `SALES_MONTHS + 3` = 9 个月、凑够 6 个有数据的月份；最近一个月每次都重抓（数据可能补录），更早且 data.json 里已有的月份直接复用。

**新车上市识别（`launches()`）**，每条 RSS 标题依次经过：

1. **去来源后缀**：标题末尾的「 - 来源名」去掉
2. **关键词过滤**：标题必须含「上市」或「预售」；含 `NOISE` 中任一词则丢弃，如「销量 / 降价 / 召回 / 财报 / 国补 / 以旧换新 / 车展 / 预计 / 或将 / 曝光 / 谍照 / 申报 / 值不值 / 什么时候 / 明年 / 多少钱 / 怎么样 / ？」（问答式 SEO 文和推测性内容不算新车上市）
3. **车型名提取**：按标点切段，取第一个含「上市 / 预售 / 发布」的片段；用 `STRIP_RE` 剥掉【】、引号、价格（售价 / 预售价 / 指导价 / 置换价 / 一口价 / 补贴后 + X 万）、日期、「正式 / 官宣 / 定档 / 即将 / 全球 / 焕新」等营销词；再取「上市 / 预售 / 发布」前面的最后一段作为车型名。最后一段是纯英文数字型号（如「MONA L05」）时把前一段一起带上；车型名截断到 24 字
4. **过滤盘点标题**：车型名少于 2 字，或命中 `新车|多款|几款|\d款新|^\d款|这两款|最近|一大波|公布|重磅|^级|vivo|香港|手机` 的，视为盘点 / 非汽车内容，车型名置空（之后整条丢弃）
5. **售价识别 `price_of()`**：正则 `PRICE_RE` 匹配「X 万」或区间「X–Y 万」（分隔符支持 `- – — ~ ～ 至`）。**只认售价**：
   - 价格前 4 个字符内出现「优惠 / 降 / 省 / 让利 / 减 / 补贴 / 送 / 返」→ 跳过（优惠金额不算售价）
   - 满足任一才采用：是价格区间；后面紧跟「起」或「万元起」；前面有「售价 / 预售价 / 指导价 / 起售价 / 权益价 / 置换价 / 限时 / 一口价 / 补贴后」
   - 输出 `[低, 高]`，单价时两者相等（前端显示「X 万起」）；都不满足则为 `null`
6. **上市日期 `DATE_RE`**：匹配「(将于|定档|官宣|于) M月D日(晚) (正式)(全球|焕新|全新)(上市|发布|开启交付)」；年份取发布时间的年份，若月份比发布月早 6 个月以上则算下一年（跨年）
7. **状态判断**：上市日期晚于新闻发布日期，或标题含「预售」且该片段去掉「预售」后不含「上市」→ `upcoming`；否则 `launched`，没识别到日期的已上市条目用新闻发布日期
8. **同车型合并去重**：`norm()` 去掉年款（`\d{4}款`）、「续航 X 公里」、`BRANDS`（比亚迪、吉利、小鹏、问界、小米等 30 个品牌）和 `GENERIC`（全新 / 新款 / 第二代…）后转小写；按发布时间倒序，归一化名互相包含即视为同一车型，保留最新一条，其它报道存入 `also`（最多 12 条），若主条目没价格则用其它报道的价格补上。归一化后为空的条目直接丢弃
9. 最终最多保留 60 条

**爱卡（`xcar()`）**：去掉 script / style / 标签后，在「最新上市」与「车型热度排行榜」之间按空白切词，遇到匹配 `\d+(\.\d+)?(-\d+(\.\d+)?)?万` 的词就把之前累积的词拼成车型名，最多 20 条。

**容错（`main()` 里的 `run()`）**：每个来源单独 try；失败时记录 `ok: false` 和错误信息（截断 120 字），`updated` 保留上次成功的时间，数据沿用 data.json 里的旧值。来源返回空结果也会主动抛错（如 `no cut data`、`no launches`），避免用空数据覆盖。

## 前端

**详情抽屉 + 列表页（通用组件 kit）**：电脑上从右侧滑出，手机上从底部升起；地址写进 hash，`#/item/<类型>/<id>` 打开详情、`#/list/<key>` 打开列表页，分享链接可直接打开对应条目；条目已下榜 / 过期（不在当前 data.json 里）时弹出「这条内容已不在当前数据里」提示。

| 条目类型 | 地址 | 内容 |
|---------|------|------|
| `series` | `#/item/series/<懂车帝车系 id>?city=<城市>` | 车系：关键信息、各城市降幅对比、近几个月销量柱状图、相关新车报道、同品牌其它降价车系，按钮跳懂车帝车系页 |
| `launch` | `#/item/launch/<launches 数组下标>` | 新车：状态、上市日期倒计时、价格、原标题、全部报道、相关车系 |
| `xcar` | `#/item/xcar/<xcar 数组下标>` | 爱卡车型：相关新车报道和车系（按车名包含关系匹配） |

| 列表 key | 地址参数 | 内容 |
|---------|---------|------|
| `cuts` | `?city=&range=&brand=&sort=` | 某城市降价榜全部车系，城市 / 价位 / 品牌筛选，按降幅或降价金额排序 |
| `sales` | `?month=YYYYMM` | 某月销量榜，按月切换 |
| `launches` | `?status=upcoming` 或 `?status=launched` | 新车上市（全部 / 即将上市 / 近期已上市） |

列表页每页 30 条（`LPAGE`），「加载更多」追加。注意 `launch` / `xcar` 的 id 是数组下标，数据更新后旧链接可能指向别的条目。

**项目特有功能**：
- 首页各栏目显示条数：降价 12（`HOME_CUTS`）、销量 10（`HOME_SALES`）、新车每栏 8（`HOME_LAUNCH`），超出显示「全部 →」进列表页
- 销量榜名次变化：对比上一个月同车系名次，显示 ↑/↓ 或「新上榜」
- 即将上市列表只显示上市日期 ≥ 今天（北京时间）的条目，按日期升序
- 右侧挂件：当前城市降价车系最多的前 6 个品牌、怎么看降价榜、来源状态（失败显示「失败 · 沿用旧数据」）
- 城市、主题保存在 localStorage（键前缀 `cd:`），默认杭州、深色主题
- `data.json` 用 `cache: 'no-cache'` 读取，更新后刷新即可见

## 本地运行

```
python3 scraper.py
python3 -m http.server 8793
# 打开 http://localhost:8793
```

- 依赖：Python 3（工作流用 3.12），只用标准库，无需 `pip install`
- 环境变量：无，不需要任何密钥
- 需要能访问 Google News（国内网络可能需要代理，否则「新车上市新闻」会失败并沿用旧数据）
- 运行结束会在终端打印各城降价数量、杭州前 3、销量冠军、新车前 12 条和失败来源

## 自动更新机制

工作流：`.github/workflows/scrape.yml`（`permissions: contents: write`，`concurrency: scrape` 不取消进行中的任务）

| 触发方式 | 时机 |
|---------|------|
| GitHub Actions 定时任务 | 每天 09:40 北京时间（cron `40 1 * * *` UTC） |
| push 到 main 分支 | 仅当改动了 `scraper.py` 或 `.github/workflows/scrape.yml` |
| GitHub Actions 手动 dispatch | 按需触发 |

- **心跳**：`data.json` 的 `updated` 字段每次运行都会变，所以每次都会产生一次 `data: update YYYY-MM-DD HH:MM` 提交（提交前 `git pull --rebase` 避免冲突）
- GitHub 规定仓库 60 天无提交会自动停用定时任务；靠上面的心跳提交保持活跃。若仍被停用，需在 Actions 页面手动重新启用
